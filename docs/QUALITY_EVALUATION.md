# Production quality evaluation

This is the repeatable review method for stage 3. [STATUS.md](STATUS.md) owns current findings and stage state. This file defines how to collect the next evidence; it does not claim that an unreviewed video is good.

## Review unit

Keep the source article, final script, rendered video, visual mode, generation settings, and provider charges together in a private local record. Each newly rendered video gets a local `*.production.json` file beside its MP4. The file records the source URL, script key, scene modes/models, generated versus reused/manual scenes, music track and mix level, preflight visual output estimate, quality gate result, finished-file SHA-256, YouTube ID, and AI disclosure choice if uploaded. New records also state the music-source loudness target; older records may omit these fields. A failed quality check after rendering also gets a record. Runs that stop before rendering do not. For an image-versus-hybrid comparison, use the same script, narration, subtitles, and editing settings; change only the visual mode. Match runs by `script_key` and start with three different topics before drawing a directional conclusion.

An upload creates `*.upload-pending.json` beside the MP4 before calling YouTube and removes it only after the returned ID reaches the production sidecar. A missing provider response or sidecar write leaves the claim in place. Check the private Shorts list in YouTube Studio before resolving it: save a confirmed video ID in the matching sidecar, or remove the claim only after confirming no upload occurred. The local marker is an attempt record, not proof that YouTube accepted the file.

For new Veo calls, `outputs/evaluation/visual_attempts/*.json` records each submitted app attempt, including ones that fail before an MP4 exists. It holds model, seconds, output count, preflight output estimate, scene number when known, status, and provider operation/error code when available; it omits the prompt and leaves actual billed USD null. A `timed_out_unknown` or `failed_or_unknown` record is neither proof of a charge nor proof of no charge. Reconcile the provider SKU detail and allocate actual cost to the relevant editorial review separately. Earlier direct pilot attempts remain in their own ignored request files.

Manual editorial re-cuts remain in the local evidence but have `paired_comparison_eligible=false` in their sidecar, so a corrected cut with the same script key does not invalidate the original mode pair. Only compare runs where visual mode is the intended difference. The scorecard treats every finished cut outside a unique eligible image/hybrid pair as a standalone editorial review, including a routine automatic upload and ambiguous repeated-mode renders. A cut count is not a count of independent topics. If multiple eligible renders of one script and mode exist, the scorecard skips that ambiguous pair; resolve the run grouping before drawing a mode conclusion.

For a local music/caption review, run `python scripts/creative_review.py BASELINE.mp4 MUSIC_ALTERNATIVE.mp4 CAPTION_ALTERNATIVE.mp4 --output outputs/evaluation/creative_review.html --names BASELINE MUSIC CAPTIONS`. The command requires the baseline and music alternative to have identical encoded video streams and different audio, and the baseline and caption alternative to have identical encoded audio streams and different video. It writes an ignored local HTML page with three video references; open it locally, or open each MP4 in a media player if the browser disallows local-file pages. This proves which encoded stream changed, not that playback works in every browser, music fits the story, captions look good, source claims are correct, or a cut is publishable. Leave the private review CSV unaccepted until the owner judges the complete videos.

For two or more music-only options, run `python scripts/music_review.py --cut '무음 기준' BASELINE.mp4 --cut '곡 A' MUSIC_A.mp4 --cut '곡 B' MUSIC_B.mp4 --output outputs/evaluation/music_review.html`. It rejects a changed video stream or repeated audio stream before writing the private page. Use the same script, narration, clips, subtitle style, and mix level for the rendered cuts; stream equality alone cannot prove those production choices or musical fit. Keep `accepted` blank until listening review.

After verifying a script against its source, run `python scripts/paired_review.py path/to/script.json --budget-usd 1.25`. The command checks a conservative visual upper estimate before TTS, creates one narration set, renders image then hybrid with that same audio, and allows one Veo request attempt. It produces local videos only. Its estimate can double-count images later reused from the scene cache; actual provider charges may also include retries and other calls outside this command.

## Record for each video

| Check | What to record |
| --- | --- |
| Technical gate | `check_video_quality` result, duration, width × height, audible narration, final audio loudness, visible scene defects |
| Source accuracy | Each concrete number, quote, named entity, causal claim, and past-tense event checked against the primary source; distinguish an assigned role or capability from an observed result and count unsupported claims |
| First five seconds | Whether the opening states a specific reason to keep watching without a generic intro |
| Story turn and payoff | A source-supported dilemma, the actual decision or result revealed early, and a clear conclusion; reject a chronological list of facts without a turn |
| Narration and pacing | Intelligibility, awkward speed changes, pauses, phrase caption timing, one-word orphan captions, whether text reveals a later fact early, and dark frames at scene cuts |
| Visual relevance | Before spending, state the source-backed relationship the viewer must **see**, plus which part comes from Veo and which from the editor. After rendering, watch silently with captions hidden: can the relationship be inferred from shapes and motion, rather than only read as labels? Check setting, counts, roles, invented marks, and whether AI illustration is distinguished from actual footage. |
| Visual rights | Original source and credit for each photo or clip, publisher usage terms and any third-party exception, recognizable people or protected logos, and whether the video implies an agency's endorsement |
| AI disclosure | Check whether any AI-generated or altered scene appears photorealistic or changes a real event/place. Record the YouTube AI-use choice and verify it before publication; obvious diagrams and script assistance alone do not require disclosure under [YouTube's guidance](https://support.google.com/youtube/answer/14328491?hl=en). |
| Visual rhythm | Distinct composition or meaningful motion across scenes; note repeated photos and static stretches even when every individual frame is accurate |
| Music | Compare the script's `music_direction` with the selected track and the full rendered scene arc by ear; record whether the bed is audible under speech, avoids masking narration, and has documented rights for publication. Intentional silence needs an editorial reason. |
| Channel distinctness | Before publication, compare the cut and its title/description with the channel's recent and most-viewed videos. Record the source-backed question, creator explanation, and visual evidence that make this episode meaningfully different; reject a cut whose story and visuals are interchangeable with another episode. This is a manual channel-level review under [YouTube's monetization policy](https://support.google.com/youtube/answer/1311392?hl=ko), not a guarantee of YPP eligibility. |
| Cost | Sidecar's preflight visual output estimate, actual provider charge attributable to the run, rejected generations, and production time |
| Outcome, if published | Video ID, publish date, retention and revenue after a consistent observation window |

Do not publish a video with a failed technical gate or an unsupported factual claim. Resolve the defect, regenerate only affected scenes when possible, and repeat the check. Human reviewers decide whether hook, narration, and visuals are good enough; the current code does not score these reliably.

## Comparison and sharing

Compare image and hybrid by accepted-video rate, actual cost per accepted video, and reviewer notes first. Standalone cuts, whether automatic or manually edited, are summarized separately from unique image/hybrid pairs, including rejected drafts when their costs are assigned. The sidecar estimate is not the provider bill: it excludes prompt tokens, narration, retries, taxes, and any charges from a failed run without a rendered video. Reconcile bills separately in the private record. Use retention and revenue only after the same observation window and enough published samples. Do not infer audience preference from the nine legacy files in the technical baseline: they were not paired experiments and have no sidecars. Keep raw articles, bills, channel metrics, sidecars, and video files outside Git. Share only anonymized counts, aggregate costs, findings, and resulting code decisions in `STATUS.md` or `DECISIONS.md`.

Run `python -m shorts_maker.services.scorecard init` after each new render to add missing rows to the ignored `outputs/evaluation/reviews.csv`. Fill `accepted` with `yes` or `no` after the checks above; mark superseded editorial drafts `no` and the chosen cut `yes` only after full review. Enter `billed_cost_usd` from the private provider records, including failed attempts and a consistent allocation of shared narration/planning cost. The optional `views_7d`, `average_view_duration_seconds_7d`, and `revenue_usd_7d` refer to the same first seven days after each public upload; leave them blank until observed. Run `python -m shorts_maker.services.scorecard summary` for paired acceptance, separate editorial-cut acceptance/cost, paired seven-day outcomes, and accepted editorial-cut seven-day outcomes. Editorial retention can be summarized before the bill arrives; cost per accepted video still waits for allocated billed cost. A YouTube ID proves an upload, not public visibility: enter outcome values only from a verified public video's seven-day window. A revenue total stays blank until every included editorial video has a revenue value. The current YouTube token only grants upload access, so these metrics must be entered from a private export until analytics read scopes are authorized.

`scorecard init` adds the `public_release_confirmed` column to an older private CSV while preserving its existing review entries. Leave it blank for private or pending videos. After the owner separately approves publication and YouTube shows the video as public, enter `yes` in that video's row; use `no` for a video that will remain private. Paired and editorial seven-day summaries require `yes` as well as an upload ID and the two observed retention fields. This is an operator attestation, not an API visibility check. Record the first complete seven-day window only after it has elapsed.
