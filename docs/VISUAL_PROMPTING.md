# Visual prompt practice

Reviewed: 2026-10-26; image-to-video guidance and implementation rechecked 2026-11-03. This guide records public techniques selected for ShortsMaker's source-grounded, low-cost workflow. [STATUS.md](STATUS.md) owns current production evidence; [DECISIONS.md](DECISIONS.md) owns durable choices. A well-written prompt improves direction but cannot prove that a generated frame is accurate.

## Prompt brief before a paid request

1. Read the primary source for actual place, time, subject count, equipment, roles, and what is a future goal rather than a completed event.
2. Choose one point the viewer should understand in this scene. For Veo, specify one shot and one movement. For Gemini stills, specify one static composition.
3. If the source cannot support a realistic depiction, request a visibly stylized explanatory image. Use a separately cleared source photo or a local diagram when accuracy depends on exact equipment or labels.
4. Leave exact words, numbers, credits, and subtitles to the editor. Review the resulting frame for extra objects, readable invented labels, setting mismatch, and any appearance of real footage.
5. State the **visible proof** for the narrated claim before camera and style instructions. A generated explanation shot must contain the required structure itself. For a narrated change, specify what is visible before, during, and after it, keeping the relevant parts in frame. Use local text for exact names, numbers, subtitles, and attribution; do not assign the core spatial or causal explanation to a later overlay. The [Sillim review](SILLIM_VISUAL_ALIGNMENT_REVIEW.md) is the regression example.

The automatic script writer now asks for that proof when narration depends on a spatial or causal relationship; the existing source validator rejects a missing relationship before visual generation. This is a prompt-level gate only. Before accepting a returned clip, watch it muted with captions and editor graphics hidden at the first frame, key change, and end. Record whether the required relationship is visible in the raw pixels. If it needs an explanatory diagram added later, reject the shot for an explanatory cut and revise only that scene's brief. Technical quality, pleasing motion, and a passing model judgment cannot replace this review.

Example for the NASA pilot: `A clearly stylized top-down diagram of one scouting drone and two distinct ground rovers on a grassy research field; one point of interest; simple shapes; calm open lower third.` The location and robot count come from the [NASA article](https://science.nasa.gov/blogs/planetary-expeditions/2026/09/15/nasa-field-tests-ai-fleet-capability-for-science-exploration/). If a real device appearance is needed, choose the credited source photo in editorial review instead of inventing one.

## Deferred techniques

- Automatic first-frame generation for every scene remains unproven. The Sillim results support reviewed, scene-specific seeds, not a blanket quality gain or removal of raw-clip and whole-cut review.
- Automatic prompt enhancement or paid multi-variant retries add calls before there is evidence that they raise acceptance rate. Keep one planned prompt and repair only rejected scenes.
- Timed multi-shot prompts may be useful for longer video, but the current six-second hook benefits from the provider's single-moment guidance.

Any prompt wording or model wrapper change that alters generated visuals must change the scene cache identity. Existing saved outputs remain on disk but must not silently stand in for a new prompt's result.

## Bounded model shots (2026-11-01)

Keep a concept model and its relevant ends inside the first frame, and prefer a bounded push toward known geometry over a traversal that reveals unseen surroundings. This is a planning heuristic, not a quality guarantee: in the Jamsu round, neither “very small lateral” nor switching to a wider input prevented newly invented structures. Inspect the returned full-duration framing before use; source-contradicting bridges or access structures must be excluded. Stop at the authorized version limit. A separately reviewed crop or dated design-page cut using an already accepted native shot may be a better edit than another paid attempt; record the repeated footage and judge the whole cut. Do not hide a failed shot’s cost or describe a derived edit as a distinct new native generation. [STATUS.md](STATUS.md) owns the current episode evidence.

## Single-scene composition and setting (2026-11-06)

The shared still-image request asks for one continuous composition rather than turning a route or action into storyboard strips or repeated subjects. Preserve comparisons or multiple conceptual views only when the brief explicitly requests them. Retain the specified place, period and architectural context; keep unverified surroundings neutral. This is a request instruction, not an automatic visual classifier or a quality guarantee.

Before approving a frame, inspect the setting as well as the focal object. An abstract route may simplify geometry, but a distinctive foreign village, landscape or building style cannot stand for a sourced Seoul urban route merely by adding a concept-model disclaimer. Use positive source-compatible forms in the brief (for example, a level urban base, concrete channel and low rectangular market canopy), without claiming exact landmark likeness or measured geography. Check the generated frame itself before motion. If a later review catches an earlier mistaken approval, retain that approval as history, reject the active frame and affected footage, and preserve all costs. A local trim is a new edit to review; it cannot erase a setting error that remains in its pixels.

## Narration detail and continuity review (2026-11-07)

For each scene, put four things in the existing `visual_description`: the narrated claim, the objects that make it visible, their spatial relationship and the framing that keeps the proof readable. Put one achievable movement, what remains in frame and the ending state in `motion_instruction`. A longer list of attractive scenery does not make a shot more explanatory. The script writer and validator now use Terra; the validator can reject a disconnected arc as `weak_story` and unexplained changes between recurring subjects as `visual_discontinuity`.

Repeat a compact **continuity anchor** verbatim in every relevant scene description: the same subject's shape, color/material, important layout and supported counts/roles, together with a coherent place/period and visual style. An independent image request receives that scene's description, not the other scenes' memory. Treat unverified appearance as visibly conceptual; never claim a chosen illustrative color or layout reproduces the real equipment. Different locations, dates, design versions, camera angles and cutaways must be explicitly distinguished rather than forced to look identical. Do not invent a bridge between unconnected places.

Examples for reviewing the retained Cheonggye claims (planning criteria only, not new approved prompts or generated footage):

| Narration needs to explain | Required native-picture detail | Continuity/rejection check |
| --- | --- | --- |
| No driver's seat at the front | The complete bounded front floor, both side boundaries and forward window; enough interior context to see where a seat could be. | Keep the same bus/window/interior geometry; reject a crop that merely looks past the front area, or an invented seat-removal event. |
| Circular seating and a forward view | The seating curve and an unobstructed line toward the same front window in one legible composition. | Preserve the earlier window and seat materials/layout; a new generic exterior bus shot adds no proof. |
| Eight passengers and a test driver | Show the supported count only through a clearly illustrative arrangement or separately reviewed source reference. | Do not invent an actual crew seat, uniform, controls or task. Role narration does not authorize an unsupported cockpit layout. |
| A night route between named places | Source-compatible urban/channel/market context, with exact names and dates supplied by narration/editor text. | Retain the bus identity and night setting; reject a distinctive foreign village or an invented exact route map. |
| Boarding/alighting card taps | A readable card/reader interaction with one bounded action and a clear end, appropriate to the scene's short duration. | Preserve card/reader/vehicle appearance; reject a camera pan that hides contact, resets the action or implies unsupported real hardware placement. |

Before spending on motion, compare every first frame with the previous accepted frames for these anchors, count and geography. After motion, watch the whole muted clip and compare its start/change/end with the narration and adjacent shots. Reject a new object, changed identity or lost explanation at the raw gate; captions cannot repair it. Then check the completed narrated cut for story progression, repetition, pace and caption contrast. Retain a specific failure reason and all costs. Prompt/validator wording and offline tests do not guarantee generated consistency, viewer interest or better retention; a new whole-cut evaluation is still required.

The November 7 Terra comparison exposed a narrower absence mismatch: narration said both driver seat and steering wheel were absent, but the scene brief named only the floor/window and a generic driver station. The strict validator rejected it before any media purchase. Before paid validation, enumerate **every absent object in the narration** and locate its complete possible volume in the visual brief: an empty floor proves neither an empty dashboard-height area nor an absent steering wheel. Name both absences explicitly and keep that volume visible through the motion. This is a writer/reviewer instruction, not a keyword-based approval or a reason to overturn the preserved failed verdict. A corrected candidate still needs its authorized new review.

The same comparison's separately owner-authorized recheck then rejected a narrated one-person count over an opaque exterior and contradictory `no people` cabin briefs. Distinguish a role-only label from a numerical count: the existing validator allows contextual footage for a role, but the count needs visible evidence. A clearly schematic human placeholder can show one accompanying person inside the cabin without claiming the real crew seat, posture, controls or work; mark that boundary and retain the same count in relevant cabin views. Never equate absent driving equipment with absent people. Preserve both failed verdicts; an owner-reassessed candidate is a new editorial decision, not a changed model score. Generated frames and full motion still need their own checks.

Manual prompt exports retain each scene's actual subject and motion instructions. Their style notes no longer impose unrelated `no people` or `4K` instructions that contradict narrated people or the selected model's supported settings. The automatic image-first motion wrapper is unchanged: the reviewed frame supplies appearance, and its motion request preserves it.

## Image-first request boundary (2026-11-03)

The v2 generator wrapper repeated `visual_description` and requested unlettered surfaces/caption space even with a reviewed first frame. That contradicted this guide and [Google's motion-only image-to-video advice](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/best-practice#prompt_for_motion_only). The v3 wrapper uses the input image for the scene/style, retains the complete reviewed motion instruction, and asks to preserve the scene outside that motion. Both normal and fallback image-first prompts omit the static description and caption-space redesign. Text-only requests still require the original scene description. This fixes request construction; it does not prove the earlier staircase/extra-bridge failures were caused solely by repeated descriptions or that the next output will pass.

The prompt-version change invalidates earlier first-frame/cache bindings for a new staged generation. Old receipts and files stay intact; an old or pending receipt cannot silently authorize resubmission or be relabelled as v3. Recheck the frame and reconcile the request identity before any future paid request. Already accepted clips can still be supplied explicitly to the local-edit path without buying replacements. Keep existing exclusions, version limits and spending authority; the consumed Jamsu scene-2 allowance does not reopen for this change.

## Reviewed appearance reference (2026-11-07)

Independent text briefs in the Cheonggye comparison produced a different wheel/body/bench design. The internal still helper now optionally accepts a reviewed PNG/JPEG appearance reference, validates its bytes/format/20MB bound before reserving, and sends it with the unchanged scene brief. Use it for the recurring subject, not as evidence of real equipment, and retain the reference hash in the request's private provenance. Existing no-reference callers are unchanged; this is not an automatic Studio or schedule feature. The new first-frame hash continues to bind the subsequent Veo request, without changing the motion wrapper.

A reference can also lock the original camera angle: the first live referenced repair restored the vehicle identity but retained its three-quarter composition. Inspect each output for both identity and the scene's required visible proof; do not claim a new viewpoint just because the prompt asked for one. Reject a failed result within the authorized version limit. Whole-cut pacing may still need local reframing using retained native clips. The output reservation guard does not include image input tokens; at the checked [Google rate](https://cloud.google.com/model-garden/pricing), a Flash-Lite image reference costs 1,120 input tokens at $0.25/M (about $0.00028), kept separate from output holds and eventual bills.
