## 재시도와 중단

**2026-11-06 사용자 회차 예외 승인:** 첫 청계천 예약 회차에만 Google 예약 상한 **₩3,300**과 4장면의 세 번째 첫 프레임 **1개**를 허용했다. 기존 ₩2,328을 보존하고, 새 4장면 첫 프레임→통과 후 무음 Lite 720p 6초 1개, 5장면 첫 프레임→통과 후 같은 6초 1개를 순서대로 진행한다. 5장면 첫 프레임 품질 실패의 수정 1회까지 새 출력 예약 최대 ₩924, 누적 최대 ₩3,252를 제안한 범위다. 자동 재시도는 없고, 월 ₩10,000·다음 회차 ₩3,000·OpenAI 권한은 유지한다. 실제 nova 길이와 원본·완성본 품질이 맞지 않으면 중단한다. 기존 4장면 제외 영상의 사용을 승인한 것이 아니다.

- Veo는 요청마다 무음 720p Lite, 4·6·8초 중 검토한 길이와 일치하는 상한을 지정하고 1개만 요청한다. SDK/공급자 오류에 대한 자동 재시도는 하지 않는다. 비용을 알 수 없는 모델로 자동 전환하지 않는다.
- 품질이 부족하다고 명확히 판정된 장면은 첫 프레임이나 연출을 수정한 **새 버전 1회까지** 같은 회차 한도에서 만들 수 있다. 동일 장면의 세 번째 유료 버전, 회차 한도 추가, 더 비싼 모델 전환은 별도 판단을 요청한다. 현재 잠수교 4장면은 이미 v1·v2 영상이 있으므로 이 안을 승인해도 세 번째 유료 버전은 자동으로 허용되지 않는다.
- TTS는 현재 코드의 1회 요청 + 일시적 오류 재시도 1회를 모두 예약 추정에 포함한다. 부분 완료 음성은 해시를 확인해 재사용한다.
- 요청 결과가 불확실하거나 업로드 ID가 확인되지 않으면 즉시 멈춰 요청/파일/장부/Studio를 대조한다. 같은 요청이나 업로드를 다시 보내지 않는다.
- 원문과 화면의 의미가 어긋나거나, 내레이션을 가리거나, 남은 비용으로 합격한 완성본을 만들 수 없으면 해당 제작을 멈추고 이유를 기록한다. 날짜를 맞추려고 품질 기준을 낮추지 않는다.
- 월이 바뀌면 그 달의 사용 기준과 장부를 확인한다. 전월 승인이나 예약액을 삭제해 새 잔여액을 만들지 않는다. 모델 종료·가격/음성 변경으로 기존 검증이 무효가 되면 먼저 호환성과 비용을 확인한다.

## 현재 잠수교에 적용할 때

1. 승인된 다섯 문장과 두 서울시 출처를 유지하고, 승인된 큰 설계안 비교와 Serene View/soft 방향을 출발점으로 삼는다. 최신 v2 원본은 사용자 재생 평가로 투명 바닥의 의미와 후반 구도가 승인됐다. 두 판을 끝까지 보여야 한다던 에이전트의 이전 제외 판정은 해당 원본에 대한 사용자 평가로 대체됐다.
2. 사용자에게 승인된 v2 4장면을 재사용하고 다시 생성하지 않는다. 여전히 제외된 3장면 철거 연출과 4장면 v1은 쓰지 않는다. 나머지 장면의 첫 프레임·연출을 검토해 전체 계획을 고정한다.
3. 비용을 확인한 최종 시각 계획을 먼저 고정한다. 여기에 묶인 새 음성 한 세트를 만들고, 음악의 말 가림·자막·호흡·출처 표현을 전체 컷에서 확인한다.
4. 원본 의미와 전체 컷이 통과하고 인증이 유효하면 중복 방지 기록을 갖춘 비공개 업로드 1회까지 진행한다. 이제 승인된 운영 범위를 적용하며, 기존의 `raw-only` 승인을 재사용하지 않는다.

- 따라서 이 안은 준비가 안 된 네 영상을 즉시 구매하겠다는 요청이 아니다. 승인 후에도 적합한 전체 계획과 상한 검증이 선행되어야 하며, 부족하면 멈춘다.

이 운영 범위는 사용자가 변경하거나 철회할 때까지 적용한다. 회차 채택 3회로 초기 운영 기반을 검증한 뒤에도 같은 월·회차 한도를 유지한다.

## 구현 상태와 실운영 검증

**2026-11-03 사용자 보완:** 완성본 피드백에 따른 개선 개발은 제작 주기와 독립적으로 더 짧은 주기로 진행한다. 기존 자산을 이용한 로컬 비교, 코드·프롬프트·프로세스 수정과 검증을 다음 제작일까지 미루지 않는다. 이 보완은 28일 제작 주기나 월·회차 지출 상한을 변경하지 않으며, 새 유료 검증·추가 회차의 자동 승인이 아니다. 실제 점검 시각과 실행 증거는 [STATUS.md](STATUS.md)가 관리한다.

월 장부, 장면별 상한, 원본 검토·재사용, 기술 검사, 비공개 업로드 중복 방지와 회차 이력은 유지한다. `scripts/operate_schedule.py`와 `services/operating_budget.py`는 제작 시작 전 두 장부의 요청 ID 기준을 한 번 저장하고, 이후 모든 월의 새 예약액을 보수적으로 합산해 회차 잔여 한도를 계산한다. 별도 프로세스에 `min(월 상한, 현재 월 사용 기준 + 남은 회차 한도)`를 적용하며 Studio의 전역 유료 스위치를 켜지 않는다. 다른 작업의 새 예약도 배분을 추측하지 않고 보수적으로 포함한다. 이는 정상 프로젝트 클라이언트의 예약 가드이며 임의 코드 실행의 보안 격리나 실제 청구 캡은 아니다.

에이전트 운영 일정은 전용 시계 호스트가 유료 호출 없이 대기 항목을 만들고, 같은 회차를 기획·검토·제작·비공개 업로드로 인계한다. 중단된 실행이나 오래된 월 장부를 새 승인으로 해석하지 않는다. 비공개 업로드 연결은 사용자 채택이 아니며 다음 RSS 회차 재개는 별도의 사용자 채택 기록을 따른다. 설정·실행 상태와 최신 증거의 소유 문서는 [STATUS.md](STATUS.md)다.
