## Production flow

The planner's OpenAI clients propagate authentication and permission errors alongside rate limits. A denied article analysis or optional enrichment cannot become a fallback script request; validation access failures are operational errors rather than editorial rejections. Existing service error handling stops the run, while original reservations and unresolved review records remain intact. Offline regressions cover 401/403 across the scoring, analysis, enrichment and validation boundaries and direct-URL stops before writing or history updates.

Writer and validator prompts distinguish observable relationships from descriptive facts: counts and spatial/causal connections require visual evidence, while a source-stated date or role must not force invented equipment, actions or crew placement. Prompt regressions preserve both sides of that boundary; they do not prove a model's editorial judgment.

Static absence briefs must show the entire relevant area and context, rather than merely looking past the missing object, without inventing a prior state or removal. `services/operating_budget.py` retains the $0.30 new-episode default and validates a separately recorded owner extension up to $0.35 without resetting its baseline or spend. `tests/test_operating_handoff.py` covers missing/mismatched approval, the unchanged future default and cumulative room.

```text
NiceGUI / scheduler
  -> AppState / ProductionService
  -> paid-production gate before new planning, narration, or visuals
  -> minimum visual-cost and local monthly-room preflight before automatic planning
  -> ScriptPlanner: RSS discovery -> bounded title/excerpt scoring -> article extraction -> source-evidenced story-fit analysis -> script -> source-grounded validation (or direct URL from extraction)
  -> review_pending: save script and pause before media or upload
Reviewed script -> Studio Generation or explicit approved_script service call
  -> reviewed first frame -> one Veo scene request -> muted raw-clip verdict (repeat per video scene)
  -> approved Veo clips + visual cost preflight -> narration duration check
  -> VideoGenerator: remaining Gemini scenes, with visual cache
  -> VideoEditor: narration, subtitles, music, render
  -> rendered-file quality check + local production sidecar -> optional YouTube upload
```

The app is a Python modular monolith. `ProductionService` owns orchestration, progress, cancellation, scene routing, and upload readiness, including pre-render metadata/source-credit checks for automatic uploads and a final check against the production record before submission. `YouTubeUploader.build_upload_body` owns the exact private request fields; `ProductionService` records that prepared body in ignored pending and successful sidecars. External API and media details stay in their own modules. The scheduler invokes the same service without browser state. Agent-operated 28-day jobs first queue a persisted attempt without calling providers. `scripts/operate_schedule.py` owns the isolated operator subprocess handoff and optional macOS queue-only host; `services/operating_budget.py` retains the episode baselines and computes conservative ceilings across months. See root README for setup and operator commands. `ScheduleManager` retains prior attempts in the ignored schedule file when a new attempt starts, clears prior episode assets from the current attempt, and supplies Studio's cross-schedule execution history. The saved full script and accepted video hash/ID support later reconciliation; these records do not themselves prove an accepted recurring series.
For a reviewed story with retained assets, `ProductionService.full_pipeline` also accepts `approved_script`, `manual_clip_paths`, and `prepared_audio_paths`. That route skips new planning and narration, reuses the normal editor and quality gate, and can continue to the same private upload path with `auto_upload=True`. The caller supplies complete scene assets and reviewed upload metadata. The ordinary topic/URL path now stops at script review.

## Runtime boundaries

- Settings load from `config/.env` or root `.env`; use `config/.env.example` as the template. Secrets are not tracked.
- `outputs/`, `temp/`, `logs/`, and local histories are runtime data, not project docs.
- `ProductionService` writes a neighboring `*.production.json` record with the finished MP4's SHA-256 for each new render when the output directory is writable; upload checks that binding before reusing a YouTube ID. A separate `*.upload-pending.json` claim prevents another provider call after an uncertain result until Studio reconciliation. Keep these local with the video.
- Each new `VideoGenerator` Veo request writes a private, prompt-free record under `outputs/evaluation/visual_attempts/` before the provider call and updates it after success, error, or timeout. One file represents one app attempt and includes the caller's request ceiling. Direct requests must supply `request_budget_usd`; the automatic scene path passes its configured visual cap. A missing or incomplete final state needs billing reconciliation. Older direct pilot requests have separate ignored request records and are not backfilled here.
- New automatic Veo scenes require a local 9:16 PNG/JPEG first frame and an approval record under ignored `outputs/evaluation/visual_reviews/`. `services/visual_review.py` binds the approval to the script, source URLs, scene narration, visual/motion brief, prompt version, image path/hash, and written pass/fail criteria. `ProductionService` checks it before narration or visual requests; `VideoGenerator` checks the image bytes again before a provider attempt. Manual clips and image-only scenes do not require this record. Older text-only Veo scene caches have a different identity and are not reused as approved input-frame clips.
- `VideoGenerator._run_veo_background_only` builds motion-focused prompts for reviewed image inputs and full scene prompts for text-only inputs. `VIDEO_PROMPT_VERSION` participates in first-frame/raw-request/video-cache identities, so a wrapper change cannot silently reuse an old result as the new prompt's output; explicit retained local edits remain available. `tests/test_review_regressions.py` checks the composed image/motion request and fallback, and `tests/test_visual_review.py` checks that old receipts stop before a reservation or resubmission.
- `ProductionService.generate_review_clip` requests one new Veo scene after the first-frame gate and a conservative cost preflight for **all remaining** scenes against the per-video cap and local monthly room, then saves the clip under ignored `outputs/clips/scenes/`. Studio plays that clip muted and records the editor's approve/reject note in an adjacent `clip.review.json`. `services/raw_review.py` binds the verdict to the exact script, first-frame hash, scene number, and raw MP4 bytes. Ordinary `produce_video` requires every non-manual Veo scene to have a valid approved cached raw clip before narration or any remaining image generation; it will not silently request a replacement. Changing the scene brief or first frame moves to a new cache identity. Direct one-shot pilot scripts retain their own reviewed-request gates; they do not use this Studio raw-clip path.
- Before its one-attempt Veo request, `generate_review_clip` creates `request.pending.json` in the scene cache using exclusive creation. It removes that marker only after a valid MP4 is saved. A missing clip with a marker blocks another request across processes until its attempt record and bill are reconciled; do not remove the marker based only on a timeout. `scripts/paired_review.py` also requires approved cached Veo raw clips before it buys shared narration; its pair estimate now covers only new image outputs, while the separately approved Veo attempt remains in the source story's earlier cost.
- When all four `GOOGLE_*` monthly budget settings are supplied, explicitly initialize the ignored `outputs/evaluation/google_budget.sqlite3` ledger with `python -m shorts_maker.services.google_budget --init` after checking the opening amount. Google image and Veo calls then reserve their model-priced output before submission. Automatic scene requests record their script's primary source URL in that ledger; the status command separates source-linked and unattributed reservations, and an existing ledger gains the optional URL column on its next reservation without losing old rows. Direct requests without a script and all older rows remain unattributed. A missing or unreadable ledger blocks calls instead of restarting at zero. The budget month follows Cloud Billing's Pacific calendar; failed calls stay reserved until billing is reconciled. `reconcile_google_no_charge(request_ids, evidence)` releases only verified unbilled submission failures or provider-limit requests, preserving their original holds and the evidence in an ignored audit table; the status command reports the released total. This is an app-local estimate gate, not a Cloud Billing balance or actual invoice.
- When the three `OPENAI_*` monthly budget settings are supplied, explicitly initialize the separate ignored `outputs/evaluation/openai_budget.sqlite3` ledger with `python -m shorts_maker.services.openai_budget --init` after reconciling the UTC month's opening usage. GPT-4o/4o-mini text calls and each `tts-1` attempt reserve before submission. Automatic and standalone narration check the remaining whole-set retry exposure before buying the first missing scene; each request still reserves separately. Article analysis, optional enrichment, writing, validation, and scene speech carry the primary source URL into future reservations; the single multi-candidate RSS scoring call remains unattributed. The status command separates source-linked and unattributed estimates, and an older ledger gains the optional URL column on its next reservation without losing rows. A missing ledger, stale month, or unpriced model blocks calls; failed requests remain reserved. The budget is optional and does not include Brave, Google, other OpenAI clients, taxes, or actual provider billing reconciliation.
- `scripts/prepare_narration.py` writes scene MP3s and a cumulative request-reserve manifest to ignored `outputs/`; its ceiling uses a caller-verified model price and bounds requests, not the provider's final bill. `ProductionService` checks this manifest's scene text and file hashes when reusing those files. Legacy scratch audio without a manifest remains possible for local review and needs human script alignment.
- On macOS, `python scripts/prepare_scratch_narration.py docs/unit_price_review_draft.json --output-dir outputs/evaluation/unit_price_20261018/scratch_audio` creates local `say`/Yuna `.aiff` scenes, a script/file-hash manifest, a combined `story_audio.m4a`, and an escaped `story_review.html` under ignored `outputs/`. Re-running it reuses verified scene files and rebuilds only the local combined review. This is a story-test voice, not final narration; the local speech service may need OS permission in sandboxed hosts.
- `services/openai_models.py` owns the pinned planning/speech roles and known shutdown dates; `VideoEditor.TTS_MODEL` exposes the speech role to narration manifests and preflight. `openai_budget.py` rejects retired requests before reserving, and a fresh `full_pipeline` checks downstream speech before paid planning. `tests/test_openai_models.py` and `tests/test_prepare_narration.py` cover shutdown boundaries, paused schedules and retained-asset continuation. This static guard is not account availability discovery or model migration. The default voice remains an editor option; Settings has no independent TTS model or voice switch.
- `AppState` is in-memory browser-session state. API settings are process-wide.
- External calls are OpenAI for planning/narration, Brave when configured for enrichment, Google for visuals, and YouTube for upload. Unit tests mock those calls.
- `PAID_PRODUCTION_ENABLED` defaults to false. The shared production service, paired-review script, and direct OpenAI/Google/Brave request helpers check it before new provider calls; it does not cap actual bills. Complete local clip and narration reviews still run.
- `full_pipeline` without `approved_script` now returns a successful `review_pending` result containing the planned script and no media or upload; the scheduler saves that script inside its ignored schedule record and pauses as `script_review_pending`. Studio's Planning tab binds its confirmation to the exact current script JSON, and the Generation tab rejects an unconfirmed or edited script. This is a script/visual-description checkpoint, not a generic reviewed-first-frame gate. `full_pipeline(approved_script=..., auto_upload=True, upload_metadata=...)` still checks saved YouTube authorization without browser interaction before rendering; an expired token may be refreshed and stored, while a revoked token stops with `YOUTUBE_AUTH_REQUIRED`. `python -m shorts_maker.uploader.youtube_uploader --auth-only` is the explicit interactive reconnection path and does not upload. A failed authentication before a manual media request clears its pending-upload claim; an uncertain request result still keeps the claim for Studio reconciliation. This OAuth check does not prove channel permissions or that a later upload will complete.
- `ProductionService` subtracts manual and cached visuals before its visual estimate. Direct `VideoGenerator.generate_clips()` and `generate_scene_clip()` also check the configured visual-output cap before generating; direct batches conservatively reserve every scene because they do not use the service cache. The standalone character-video helper checks one silent Veo clip against the same cap.
